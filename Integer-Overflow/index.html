Integer overflow lab

OWASP A04:2021 · Insecure Design | CWE-190

A toy shop that stores the total in a signed 32-bit integer. Everything runs in your browser; nothing is sent anywhere.

The vulnerable code 
function buy(qty) {
  const realTotal = PRICE * qty;      // what it should cost
  const total = (PRICE * qty) | 0;    // VULNERABLE: wraps to signed 32-bit
  let status;
  if (total <= wallet) {
    wallet -= total;
    status = "Purchased";
  } else {
    status = "Not enough funds";
  }
  return { realTotal, total, status };
}

The red line is where the overflow happens. The payloads only work while the Vulnerable switch is ON. Reload the page to reset the wallet.

The fix 
function buySafe(qty) {
  const realTotal = PRICE * qty;      // what it should cost
  if (!Number.isSafeInteger(qty) || qty < 1 || qty > 100) {   // FIX: reject unreasonable quantities
    return { realTotal, total: realTotal, status: "Order rejected: quantity exceeds the maximum allowed per customer (100)." };
  }
  const total = PRICE * qty;          // no truncation
  let status;
  if (total <= wallet) {
    wallet -= total;
    status = "Purchased";
  } else {
    status = "Not enough funds";
  }
  return { realTotal, total, status };
}

The green line is the fix. It rejects the quantity before any math happens, so the total can never wrap.

Impact

Integer Overflow can lead to incorrect calculations, financial losses, and bypassing security checks. A real example occurred in 2018, when attackers exploited an Integer Overflow vulnerability in Beauty Ecosystem Coin (BEC), allowing them to transfer massive amounts of tokens without having sufficient balance.
